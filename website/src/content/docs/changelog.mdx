All notable changes to indycheck, newest first. The full changelog lives in [`CHANGELOG.md`](https://github.com/dusmamud/indycheck/blob/main/CHANGELOG.md) in the repo. All crates, npm and PyPI packages share one version in lockstep.

## [0.2.4] - 2026-11-13

The 0.2.4 release publishes the new language packages for the first time and bundles the Flutter native library. Live on crates.io, npm, PyPI, Maven Central and Packagist, with C archives and the Swift XCFramework on the GitHub release. The Flutter package's pub.dev upload for 0.2.4 is in progress.

### Added

- **Flutter / Dart: native library now bundled.** The package ships a Native Assets build hook that downloads the prebuilt `libindycheck_ffi` for the target platform from the GitHub release (SHA-256 verified) — no more manual `cargo build`. Plus a real Flutter example app (validate PAN/Aadhaar, English + Hindi reasons). Requires Dart `>=3.14.0` / Flutter 3.50+. See the [Flutter & Dart page](/flutter/).
- **Kotlin on Maven Central (first publish).** `io.github.dusmamud:indycheck:0.2.4` — Gradle Android library (AAR) with the UniFFI Kotlin bindings and native `.so` for 4 ABIs, signed and published to Maven Central. See the [Kotlin page](/kotlin/).
- **PHP on Packagist.** `dusmamud/indycheck` 0.2.4 (and 0.2.3) — `composer require dusmamud/indycheck`. FFI tier: needs the prebuilt `libindycheck_ffi.so` + `ffi.enable=true`. See the [PHP page](/php/).
- **C archives on the GitHub release.** Prebuilt `libindycheck_ffi` for 12 platforms (Linux gnu/musl, macOS arm64/x64, Windows gnu/msvc, Android 4 ABIs, iOS arm64 + simulator) + `SHA256SUMS.txt`. See the [C API page](/c/).
- **Swift XCFramework on the GitHub release.** `IndyCheckFFI.xcframework.zip` (iOS arm64 + simulator, macOS universal). The Swift Package Manager package (`indycheck-swift`) is being updated to 0.2.4. See the [Swift page](/swift/).
- **pub.dev automated publishing.** The Flutter package now publishes to pub.dev via GitHub OIDC (tag push + dispatch), wired into the release workflow — no manual upload, no token.

### Fixed

- **Go Windows link fix.** The cgo wrapper now links `-lsynchronization` too (new Rust std uses `WaitOnAddress` / `WakeByAddress`).
- **C archives: musl is static-only** (cargo drops the cdylib for the musl target) and **iOS simulator is arm64-only** (the x86_64 simulator target is unsupported on ARM64 macOS runners).
- **pub.dev score fixes.** The Flutter package description is now 149 chars and the dangling doc comment is fixed, so the pub.dev score should be 160/160 on the 0.2.4 publish.
- **Dart + PHP version tests** are now synced by `sync-versions.sh`, so the next version bump won't break them.

## [0.2.3] - 2026-11-13

The 0.2.3 release adds new language packages and the native bindings behind them. Published to crates.io, npm and PyPI on 2026-11-13. The Flutter, PHP, Go, Kotlin, Swift and C packages lived in the repo only at this release — their first published versions came in 0.2.4 above (see each language page for its exact install status).

### Added

- **Flutter / Dart package (`packages/flutter`).** Pure-Dart package over `dart:ffi`: 14 validators (including the `validateVehicleRegistration` / `validateEpic` aliases), `detect`, `validateMany`, `version()` and all 6 test-data generators. Requires Dart SDK `>=3.4.0` and `ffi ^2.1.0`. At this release it was not on pub.dev yet — install as a git dependency — and the native library was not shipped; build it with `cargo build -p indycheck-ffi --release`. (0.2.4 bundles the native library via a build hook.) See the [Flutter & Dart page](/flutter/).
- **PHP package (`packages/php`).** FFI binding (`dusmamud/indycheck`, PHP `>=8.1`, `ext-ffi`, `ffi.enable=true`): 23 methods — 14 validators, `detect`, `validateMany`, `version()` and all 6 generators — covered by 16 PHPUnit tests. At this release it was not on Packagist yet — install from the repo as a VCS repository. (0.2.4 is on Packagist.) See the [PHP page](/php/).
- **Go package (`packages/go`).** cgo wrapper over the C API, module `github.com/dusmamud/indycheck-go`: 14 validators, `Detect`, `ValidateMany`, `Version()`. No version tag yet, so `go get` does not work — use a `replace` directive until a tag is pushed. The Go package has no `Generate*` helpers yet. See the [Go page](/go/).
- **Kotlin and Swift bindings (`crates/indycheck-uniffi`).** Generated UniFFI bindings: 12 validators, `detect` and `validateMany`, with `parsed` as a JSON string. Compile-verified in CI with a `validatePan` smoke test only. At this release they were not distributed — no Maven Central artifact, no Swift Package Manager package; copy the generated files into your project. (0.2.4 publishes Kotlin to Maven Central and ships the Swift XCFramework.) No `validateEpic` alias, no generators, no `version()`. See the [Kotlin page](/kotlin/) and [Swift page](/swift/).
- **C API (`crates/indycheck-ffi`).** Six new `indycheck_generate_*` exports (`generate_pan`, `generate_aadhaar`, `generate_gstin`, `generate_mobile`, `generate_vehicle`, `generate_vehicle_bharat`), bringing the header to 24 functions. The header is regenerated with cbindgen and checked for drift in CI. See the [C API page](/c/).
- **Node.js native addon (`crates/indycheck-napi`).** napi-rs addon as an optional backend for the npm package (`packages/js/src/native.ts`, `backend()` / `isNativeAvailable()`), falling back to the pure-TypeScript mirror when the `.node` is not built. The `.node` is not shipped in the npm package. See the [Node.js native addon page](/node-napi/).

### Fixed

- **napi-rs macOS link fix.** The addon now builds with napi-build 2 + `build.rs`, so the macOS build links correctly.
- **Go Windows link fixes.** The cgo wrapper now links `-lws2_32 -luserenv -lbcrypt -lntdll` explicitly — MinGW `gcc` does not link the Windows system libraries the Rust standard library needs, the way MSVC's `link.exe` does.
- **Kotlin / Swift / C CI fixes.** Swift passes the UniFFI modulemap explicitly to `swiftc`; the C header drift check runs on Linux only (CRLF line endings on Windows made it fail spuriously).

### CI

- **Seven new test workflows, all green:** C API, Flutter, Go, Kotlin, Node napi-rs addon, PHP and Swift — each builds and tests its binding on every push.

## [0.2.2] - 2026-11-12

### Added

- **CLI: `indycheck update`.** Prints the installed version, checks crates.io for a newer one (via `curl`, falling back to `cargo search`) and prints the `cargo install indycheck --force` command. It never installs anything by itself and still exits 0 when offline. See the [CLI page](/cli/).
- **Vehicle test-data generators.** `generate_vehicle()` (state format, e.g. `DL01AB1234`) and `generate_vehicle_bharat()` (Bharat format, e.g. `22BH1234AA`) in the Rust core, JS package, Python package and WASM bindings, plus `indycheck generate vehicle` / `generate vehicle-bharat` in the CLI.
- **npm Trusted Publishing.** New `.github/workflows/npm.yml` publishes to npm via GitHub OIDC (`npm publish --provenance`) — no token, no staged publish, no passkey approval.

### Changed

- **Python bindings: PyO3 upgraded 0.22 → 0.30.** `indycheck-py` now builds on Rust edition 2024 like every other crate.
- **WASM workflow installs `wasm-opt`** (Binaryen) so wasm-pack optimizes the playground WASM instead of silently skipping that step.

### Fixed

- **Docs truthfulness.** The Test-data generators page no longer claims a `generate(type)` dispatcher or `generateIfsc` / `generateUpi` / `generatePincode` / `generateTan` / `generateCin` / `generateLlpin` / `generateEpic` helpers — those never existed in the package. Only the real generators are documented.

## [0.2.1] - 2026-11-12

### Fixed

- **Python wheel: validators no longer throw on non-string input.** `validate_pan(None)` or `validate_pan(123)` used to raise `TypeError`; they now return a `ValidationResult` with code `INVALID_TYPE`, like the JS wrapper.
- **Python wheel: Options support.** `validate_*_with_options` and the `Options` class (`default_options()`, `lenient_options()`, `no_spaces_hyphens_options()`) now exist, matching the Rust core and JS package.
- **Python wheel: `generate_pan()` and `generate_gstin()` work with no argument** (defaults: entity `P` / state code `18`).
- **Python wheel: `indycheck.pydantic` now ships in the wheel**, with a `pydantic` extra (`pip install 'indycheck[pydantic]'`).
- **README Rust snippet did not compile** — `validate_pan_with_options(..., &opts)` took the options by reference; the function takes them by value.

### Added

- **CLI: `indycheck --version`** (also `version` and `-V`) prints `indycheck <version>`.

## [0.2.0] - 2026-11-12

### Added

- **Bharat (BH) series vehicle numbers are now accepted: `22BH1234AA`** (`YYBH####XX` — registration year 21+, `BH`, 4-digit number 0001–9999, 2 suffix letters excluding `I`/`O`). `validateVehicle` returns `series_type: "bharat"` with `year`/`suffix` in `parsed`; state-format numbers now also return `series_type: "state"`. Mirrored in the JavaScript and Python wrappers, and in the [playground](/playground/) and the landing-page demo.
- See the [Vehicle page](/vehicle/) for the full BH rules and examples.

## [0.1.2] - 2026-11-12

### Fixed

- `rust-version` is now inherited by the core crate, so crates.io shows the minimum supported Rust version (1.85) instead of blank.
- First release published via crates.io Trusted Publishing (GitHub OIDC) instead of a long-lived API token.

## [0.1.1] - 2026-11-12

### Fixed

- crates.io page had no README: core crate now sets `readme = "../../README.md"`, plus `keywords` and `categories`, so the README renders on crates.io.
- Rust edition upgraded 2021 → 2024 (`rust-version = "1.85"`). No API change.

## [0.1.0] - 2026-11-11

### Added

- Rust core (`indycheck` crate): offline validators for mobile, PAN, Aadhaar (Verhoeff), GSTIN (Mod-36 Luhn), IFSC, UPI, PIN code, TAN, CIN, LLPIN, Voter ID (EPIC) and vehicle registration.
- `ValidationResult { valid, code, reason_en, reason_hi, parsed }` — never throws on bad input; stable machine-readable error codes.
- Options (`strict` / `lenient`, `allow_spaces_hyphens`, `normalise_plus91`, `uppercase`) and `validate_*_with_options`.
- `format_pan`, `format_gstin`, `format_mobile`, `mask_pan`, `mask_mobile`, `mask_aadhaar` (UIDAI-style `XXXX XXXX 0124`).
- `detect` (auto-detect) and `validate_many` (bulk batch).
- Mock test-data generators — syntactically valid test data only, never real IDs.
- CLI binary: `indycheck validate <type> <value>`, `detect`, `generate`.
- WASM bindings and Python bindings (PyO3 + maturin, abi3 wheel).
- TypeScript wrapper + Zod schemas; Python wrapper + Pydantic v2 types.
- Website: Astro 5 + Starlight docs, landing page and in-browser WASM playground (Pagefind search, sitemap).

### Known limitations

- PAN, IFSC, TAN, CIN, LLPIN, Voter ID and vehicle registration have no public checksum — format only. This is format + checksum validation, **not** KYC verification; no UIDAI/NSDL/GSTN connection.
- Bharat-series vehicle numbers were not accepted in v0.1 — fixed in v0.2.0 above.
