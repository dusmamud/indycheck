Never show a full Aadhaar or PAN on screen if you can avoid it — and never put one in a log. indycheck's masking helpers return a display-safe version, and the formatting helpers return the conventional display form.

There is no generic `mask(type, value)` or `format(type, value)` dispatcher. Masking and formatting are per-type functions, and they differ by language — read the table below before you copy a snippet.

## Masking

| Function | JS/TS | Python | Rust | Returns |
| --- | --- | --- | --- | --- |
| Mobile | `maskMobile(value)` | `mask_mobile(value)` | `mask_mobile(value)` | `"******3210"` — `""` when the input is not a valid-format mobile |
| PAN | `maskPan(value)` | `mask_pan(value)` | `mask_pan(value)` | `"AAAPL****C"` — `""` when the input is not a valid-format PAN |
| Aadhaar (string) | `maskAadhaarString(value)` | `mask_aadhaar_string(value)` | `mask_aadhaar(value)` | `"XXXX XXXX 0124"` — `""` when the input is not 12 digits |
| Aadhaar (validated) | `maskAadhaar(value)` | `mask_aadhaar(value)` | — | A full `ValidationResult`; the masked value is in `parsed.masked` |

```js
import { maskMobile, maskPan, maskAadhaarString, maskAadhaar } from 'indycheck';

maskMobile('9876543210');        // '******3210'
maskPan('AAAPL1234C');           // 'AAAPL****C'
maskAadhaarString('234567890124'); // 'XXXX XXXX 0124'
maskAadhaar('234567890124');     // { valid: true, ..., parsed: { masked: 'XXXX XXXX 0124' } }

maskMobile('5123456789'); // '' — not a valid-format mobile, so nothing is masked
maskPan('NOT-A-PAN');     // '' — invalid values are never masked
```

There are no `maskGstin`, `maskUpi`, `maskTan` or `maskEpic` helpers — only mobile, PAN and Aadhaar can be masked.

### Masking rules

| Type | Masked form | What is kept |
| --- | --- | --- |
| Aadhaar | `XXXX XXXX 0124` | Last 4 digits |
| PAN | `AAAPL****C` | First 5 letters + last letter |
| Mobile | `******3210` | Last 4 digits |

A masked value proves nothing about the ID — a non-empty result is **not** proof of validity. `maskAadhaarString` / the Rust `mask_aadhaar` mask any 12-digit string, even one whose checksum fails; `maskAadhaar` (JS/Python) only succeeds for a fully valid Aadhaar number. When in doubt, use `validateAadhaar` and read `parsed.masked`.

## What you get for free

`validateAadhaar` already returns the masked value in `parsed.masked` — you don't need a separate call:

```js
import { validateAadhaar } from 'indycheck';

const r = validateAadhaar('234567890124');
if (r.valid) {
  db.save({ aadhaar_masked: r.parsed.masked }); // 'XXXX XXXX 0124'
  // Never save the full number unless you have a lawful reason
  // and proper safeguards.
}
```

## Formatting

| Function | JS/TS | Python | Rust | Returns |
| --- | --- | --- | --- | --- |
| Mobile | `formatMobile(value)` | `format_mobile(value)` | `format_mobile(value)` | JS/Python: the `validateMobile` result (`parsed.normalized` is the 10-digit number). Rust: `Some("9876543210")`, or `None` |
| PAN | `formatPan(value)` | `format_pan(value)` | `format_pan(value)` | `"AAAPL1234C"` (upper-cased, spaces/hyphens stripped), or `null` / `None` |
| GSTIN | `formatGstin(value)` | `format_gstin(value)` | `format_gstin(value)` | The formatted GSTIN, or `null` / `None` |

```js
import { formatMobile, formatPan, formatGstin } from 'indycheck';

formatMobile('9876543210').parsed.normalized; // '9876543210'
formatPan('aaapl1234c');    // 'AAAPL1234C' (uppercased)
formatGstin('27aaapl1234c1ze'); // '27AAAPL1234C1ZE'
formatPan('NOT-A-PAN');     // null — invalid values are never formatted
```

`formatGstin` checks the GSTIN structure (state code, PAN part, `Z`) but **not** the check digit — a `formatGstin` result can still fail `validateGstin`. There are no `formatAadhaar`, `formatVehicle` or `formatLlpin` helpers — and a hyphenated LLPIN (`AAA-1234`) is not valid input at all (see the [LLPIN page](/llpin/)).

## Python and Rust

```python
from indycheck import mask_aadhaar_string, mask_pan, mask_mobile, format_mobile, format_pan

mask_aadhaar_string("234567890124")  # 'XXXX XXXX 0124'
mask_pan("AAAPL1234C")               # 'AAAPL****C'
mask_mobile("9876543210")            # '******3210'
format_mobile("9876543210")["parsed"]["normalized"]  # '9876543210'
format_pan("aaapl1234c")             # 'AAAPL1234C'
```

```rust
use indycheck::{format_mobile, format_pan, mask_aadhaar, mask_mobile, mask_pan};

assert_eq!(mask_aadhaar("234567890124"), "XXXX XXXX 0124");
assert_eq!(mask_pan("AAAPL1234C"), "AAAPL****C");
assert_eq!(mask_mobile("9876543210"), "******3210");
assert_eq!(format_mobile("9876543210").as_deref(), Some("9876543210"));
assert_eq!(format_pan("aaapl1234c").as_deref(), Some("AAAPL1234C"));
```

In Rust, `format_*` returns `Option<String>` and `mask_*` returns a plain `String` (`""` on invalid format). In JS and Python, `formatMobile` returns a full `ValidationResult` and `maskAadhaar` returns a full `ValidationResult` — only `formatPan` / `formatGstin` return a plain string or `null` / `None`.

## Rules for handling masked data

- **Store the masked value, not the full one**, unless you have a lawful reason and proper safeguards — especially for Aadhaar, which is sensitive personal information under Indian law.
- **Never log full IDs.** Log the masked value and the error `code` instead — that is enough to debug a validation failure.
- **Mask before you render.** Apply the mask at the point you build the response or the UI, not at the point you read the input — that way a future code path can't accidentally leak the raw value.

<Aside type="caution" title="Masking is not verification">
  A masked value proves nothing about the ID — `XXXX XXXX 0124` only tells you the last four digits of a number whose checksum passed. Masking protects privacy; it does not make a fake ID real.
</Aside>
