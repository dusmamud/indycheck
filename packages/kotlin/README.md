# indycheck — Kotlin / Android library (Maven Central)

Offline format + checksum validation for Indian IDs (PAN, Aadhaar, GSTIN,
IFSC, UPI, mobile, PIN, TAN, CIN, LLPIN, Voter ID / EPIC, vehicle numbers
including Bharat (BH) series) for Kotlin/Android. Thin UniFFI bindings over
the Rust core — no validation logic lives here.

Published to Maven Central as:

```kotlin
// build.gradle.kts (Kotlin DSL)
implementation("io.github.dusmamud:indycheck:0.2.3")
```

```groovy
// build.gradle (Groovy)
implementation 'io.github.dusmamud:indycheck:0.2.3'
```

## Layout

| Path | What it is |
| --- | --- |
| `indycheck/` | Android library module (the published AAR) |
| `indycheck/src/main/java/` | (empty — the Kotlin sources come from the Rust crate, see below) |
| `indycheck/src/main/jniLibs/` | Built `.so` files — generated by cargo-ndk at build time, **never committed** |
| `scripts/build-native-libs.sh` | Builds `libindycheck_uniffi.so` for the 4 Android ABIs |
| `gradle.properties` | `indycheckVersion` — lockstep version, synced by `scripts/sync-versions.sh` |

The generated UniFFI Kotlin bindings live in the Rust crate
(`crates/indycheck-uniffi/bindings/kotlin/`, package
`uniffi.indycheck_uniffi`) and are referenced from the module via
`sourceSets` — there is a single source of truth, no copy. Do not edit the
generated file by hand; regenerate it as described in
`crates/indycheck-uniffi/README.md` (uniffi-bindgen 0.28.3).

The native library is loaded through JNA (`net.java.dev.jna:jna:5.16.0`,
an `api` dependency, so consumers get it transitively).

## Building locally

Requires JDK 17, the Android SDK (API 34 + NDK), Rust, and cargo-ndk:

```sh
# one-off setup
rustup target add aarch64-linux-android armv7-linux-androideabi \
    i686-linux-android x86_64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
export ANDROID_HOME=$HOME/android-sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018

# build the AAR (native .so files are built automatically)
./gradlew :indycheck:assembleRelease

# publish to the local Maven repo (no secrets needed) and inspect it
./gradlew :indycheck:publishToMavenLocal
ls ~/.m2/repository/io/github/dusmamud/indycheck/0.2.3/
```

## Publishing to Maven Central

Publishing uses the vanniktech Maven Publish plugin (0.37.0) against the
Sonatype **Central Portal** (OSSRH/JIRA staging is retired — do not use
it). The workflow `.github/workflows/kotlin-release.yml` builds the AAR,
signs it, and runs:

```sh
./gradlew :indycheck:publishAndReleaseToMavenCentral --no-configuration-cache
```

The plugin uploads a deployment bundle to the Central Publisher API and
polls until it reaches `PUBLISHED` (or `FAILED`, which fails the build).
`release.yml` dispatches this workflow automatically after every release
with the new tag as ref, so each release auto-publishes to Maven Central.

### Secrets required (repo Settings → Secrets and variables → Actions)

| Secret | What it is |
| --- | --- |
| `MAVEN_CENTRAL_USERNAME` | Sonatype Central Portal user token username |
| `MAVEN_CENTRAL_PASSWORD` | Sonatype Central Portal user token password |
| `GPG_PRIVATE_KEY` | Armored GPG private key (`gpg --export-secret-keys --armor <KEYID>`) |
| `GPG_PASSPHRASE` | Passphrase of the GPG key |

Without them the publish job fails fast with a clear message; the AAR
build job needs no secrets. The groupId `io.github.dusmamud` is verified
on the Central Portal (GitHub-signup auto-verification); the namespace
must stay verified or the upload is rejected.

## API

Top-level functions in package `uniffi.indycheck_uniffi` (all return
`ValidationResult`, except `detect` which returns a `String`):

`validatePan`, `validateAadhaar`, `validateGstin`, `validateIfsc`,
`validateUpi`, `validateMobile`, `validatePincode`, `validateVehicle`,
`validateTan`, `validateCin`, `validateLlpin`, `validateVoterId`,
`detect`, `validateMany`.

There is no `validateEpic` alias (use `validateVoterId`), no generators
and no `version()` — the UniFFI interface has only the 12 validators,
`detect` and `validateMany`. `ValidationResult.parsed` is a JSON string
(or `null`).

```kotlin
import uniffi.indycheck_uniffi.*

val pan = validatePan("ABCDE1234F")
println(pan.valid)      // true
println(pan.code)       // VALID
println(pan.reasonHi)   // PAN ka format sahi hai. ...
```
